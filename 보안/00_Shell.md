# 00_Shell

> 보안취약점에서의 Shell

보안취약점 네이밍을 보면 "XXXShell"이라는 이름을 볼 수 있다.

여기서 말하는 Shell의 의미에 대해 학습한다.

## 1. shell의 의미

일반적으로 shell(쉘)은 운영체제의 명령어 인터프리터(bash, cmd, powershell 등)를 의미한다.

보안적인 용어(해킹 용어)로는 이보다 한 단계 더 나아가서 "**공격자가 대상 서버에서 명령어를 실행할 수 있는 상태(접근권)**" 자체를 의미하며, "shell을 땄다(get a shell)"로 표현한다.

### 1) 왜 shell이라고 부르나

shell은 사용자가 OS에 명령어를 내리는 창구다.

- bash 터미널에 명령어를 입력하는 예시

```bash
ls
cat /etc/passwwd
whoami
```

해커(공격자) 입장에서 목표는 상대방 서버를 무너뜨리는 것이고, 이는 곧 "서버에서 내 마음대로 명령어를 실행하는 것"을 의미한다.

그래서 RCE (Remote Code Execution, 원격 코드 실행)에 성공하는 것을 "shell을 얻었다"라고 부른다.

즉, 공격자는 물리적으로 해당 서버에 접근(서버 비밀번호 탈취를 통한 접근 등)해서 공격할 수도 있지만, 다른 루트를 통해 간접적으로도 접근 제어를 할 수도 있는 것이다.

<br>

### 2) shell 관련 용어

| 용어          | 의미                                                         |
| ------------- | ------------------------------------------------------------ |
| shell         | 대상 서버에서 명령 실행이 가능한 상태                        |
| web shell     | 웹 서버에 심어둔 악성 스크립트. url로 접속하면 명령을 실행해주는 백도어 |
| reverse shell | 상대방 서버가 공격자쪽으로 먼저 접속해와서 shell을 넘겨주는 방식. 방화벽의 인바운드 차단을 우회 가능 |
| bind shell    | 상대방 서버가 포트를 열고 대기하면 공격자가 접속하여 공격하는 방식 |
| RCE           | 원격 코드 실행. shell을 얻는 대표적인 경로                   |
