## 2. SSRF

공격자가 **서버가 대신 요청을 보내도록 조작**해서, 원래는 외부에서 접근 불가능한 내부 리소스(내부 네트워크, 포트 정보, 클라우드 메타 데이터, localhost 서비스 등)에 접근하는 공격 방식.

공격자는 본인이 직접 접근할 수 없는 곳을, 서버의 신뢰를 받는 위치를 빌려서 접근한다.

서버가 사용자 입력을 신뢰하고, 서버에서 사용자가 준 URL을 실행할 때 발생할 가능성이 있는 공격 패턴이다. 보통 URL을 통한 이미지 미리보기, 이미지 다운로드, 웹훅, PDF 생성기 등의 기능에서 주로 발생할 수 있다.

### 1) 발생 이유

웹 서비스는 종종 사용자가 준 URL을 서버가 대신 호출하는 기능을 제공한다.

사용자는 URL을 서버로 전달하고, 서버는

- 링크 미리보기
- 프로필 사진 업로드/다운로드
- PDF/스크린샷 생성기
- 웹훅의 콜백 URL 등록

등을 수행할 수 있다.

### 2) 원리

서버가 내부망에 위치해 있을 때, 내부망 안의 다른 서비스는 방화벽에 의해 밖에서의 접근이 막혀있지만 서버 자신은 접근이 가능하다. 이를 이용해서 공격자는 특수한 URL로 서버가 대신 요청을 보내게 함으로써 내부 리소스 정보를 획득할 수 있게 된다.

이 특수한 URL은 외부에서 접근할 수 없는 주소이지만, 서버는 최종적으로 해당 값이 정상적이든 비정상적이든 호출을 한 다음에 HTTP 응답을 반환해야하기 때문에 공격자는 서버가 호출한 결과를 보고 원하는 정보를 획득하는 것이다.

### 3) 예시

#### (1) 정상 요청

```
정상 요청:
POST /api/preview
{ "url": "https://example.com/image.png" }
→ 서버가 example.com 에서 이미지를 가져와 미리보기 생성
```

#### (2) 비정상 요청 (공격 요청)

```
공격 요청:
POST /api/preview
{ "url": "http://169.254.169.254/latest/meta-data/iam/security-credentials/" }
→ 서버가 자기 자신의 클라우드 IAM 임시 자격증명을 가져와서
  그 응답을 공격자에게 그대로 반환 (미리보기 형태로)
→ 공격자는 이 자격증명으로 클라우드 리소스에 접근 가능
```

- 169.254.169.254는 127.0.0.1과 같이 특수한 대역에 속하는 주소로, 라우팅이 안 되는 주소면서 같은 네트워크 안에서만 유효한 주소이다.
  - 보통 클라우드 서비스 프로바이더들이 이 특수한 대역의 주소를 메타데이터 서비스용으로 사용하고 있다.
  - 따라서 공격자가 입력한 이 주소로 서버가 호출을 하면, 자기 자신의 내부망 네트워크의 리소스 정보에 대해서 요청을 보내게 되고 이를 요청자(공격자)에게 HTTP 응답으로 제공하므로써 의도하지 않게 민감한 정보를 응답하게 된다.

#### (3) 보안 취약적인 코드

```java
@PostMapping("/preview")
public ResponseEntity<byte[]> preview(@RequestParam String url) {
    // 검증 없이 사용자가 준 URL로 바로 요청 -> SSRF 취약점
    RestTemplate restTemplate = new RestTemplate();
    byte[] data = restTemplate.getForObject(url, byte[].class);
    return ResponseEntity.ok(data);
}
```

### 4) 방어 방법

#### (1) 화이트 리스트 방식

- 허용된 도메인, IP만 요청이 가능하도록 제한
- 가장 안전하지만, 유연성이 떨어지는 방식

#### (2) 네트워크 레벨 격리

- 해당 서버가 애초에 내부망/메타데이터 서버에 직접 접근하지 못하도록 방화벽 및 보안그룹을 설정
- 가장 안전한 방어 방법

#### (3) 리다이렉트 미허용

- HTTP 클라이언트가 자동으로 리다이렉트를 따라가지 않도록 설정

#### (4) DNS resolve 후 IP 검증

- URL을 resolve한 실제 IP가 사설 대역인지 요청 직전에 재확인하여, 사설 대역일 경우 요청하지 않는 방식
